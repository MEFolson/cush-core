## 1. Cush in one paragraph

Cush is an AI native financial technology group building on one stack. Cush Core is AI native core banking for global banks, Tier 1 banks and central banks: one licensable system of record that puts the product catalogue, orchestration, an immutable ledger and multi rail connectivity under one control plane, while the institution keeps its licence, its brand and its books. [ONE PAGER] [SITE] Inside Cush Core sits the Cush Blockchain, a permissioned, immutable ledger designed for banks. [MATTHEW, 14 Nov 2026] Cush Payments, the first tenant on Cush Core, is set to become the de facto Africa payments platform, moving money from the diaspora to families and businesses across Africa. It is planned and has not launched. [MATTHEW, 20 Nov 2026] [DECK] The group also names Cush Cash and the Cush Foundation as propositions (section 3).

## 4. Technology, layer by layer

Primary source: [JOSE]. Where the public site adds design detail, it is tagged [SITE]. Nothing here is a performance, certification or production claim.

Proprietary versus open source: no source states which Cush Core components are proprietary and which are open source. UNKNOWN (ask Jose).

Layer 1. Architecture model. Cush Core is a distributed platform: a set of APIs that together control functionality end to end. Each API is built the same way, as an end to end vertical, isolated from the others so it is easier to control, change and upgrade. Authentication is common to all. Named modules: authentication, ledger, payments, fraud detection, document management. Accounts and cards as separate modules: UNKNOWN (ask Jose). [JOSE]

Layer 2. Ledger: the Cush Blockchain. The platform is integrated with a distributed ledger on a peer to peer network; some nodes run the ledger, others run other functions, and interaction with external parties goes through that network. The ledger is object driven: transactions, risks and issues can all be stored on it, and in the design smart contracts control transactions. Governance, control and audit sit on the ledger; an audit firm could run a read only node. [JOSE] Hashing uses BLAKE3. [MATTHEW, 19 Oct 2026] Published design: there is no single global chain; every customer, account and contract has its own append only, hash linked chain; nodes are known and registered; chains are spread across shards backed by PostgreSQL; shard failover is agreed by a quorum of coordinators; there is no general purpose consensus. [SITE, Jose's article "The Cush Blockchain: a ledger built for banks, not for public consensus"] Measured throughput and failover performance: UNKNOWN (ask Jose).

Layer 3. Orchestration and AI. Cush Core is AI native. In the design, AI agents have their own identity, permissions and audit trail, act only inside the mandate the institution writes, and every action is recorded. AI is advisory only: models explain, summarise and suggest; postings are designed to be made by deterministic smart contracts, and AI never writes to the ledger. [SITE] [MATTHEW, 14 Nov 2026]

Layer 4. Product catalogue. Products are designed to be configured from governed, versioned blueprints rather than through a change programme per product. [SITE] [ONE PAGER]

Layer 5. Rails. The one pager and site describe a design in which inbound and outbound schemes post to and leave from the same ledger, with no second payments hub. Jose's briefing marks named payment rails as unconfirmed: UNKNOWN (ask Jose). [JOSE] [ONE PAGER] [SITE]

Layer 6. Security. In place per Jose: encryption at rest at database and API level; fully stateless APIs; data segregated by type (for example session data on its own database server); granular access control that strips out fields a user may not see before the API processes the request; document classifications. Fraud detection is built in; detailed fraud controls: UNKNOWN (ask Jose). Risk, compliance and regulatory reporting are built in. [JOSE] [MATTHEW, 19 Oct 2026]

Layer 7. Standards and certifications. Cards are intended to be supported through card aggregators, which avoids handling PCI DSS directly; Jose says the system could meet PCI DSS if needed. ISO standards will be used where needed to work with third party payment networks; which ISO standard: UNKNOWN (ask Jose). ISO 27001 and SOC 2 status: UNKNOWN (ask Jose). No certification is claimed. [JOSE]

Layer 8. Deployment. The bank's choice: public cloud, the bank's own premises, or a mix. This is a networking choice that does not change the applications. Scales from a single laptop (how Cush runs its tests) to a large, partitioned system. Specific API names, standards and connection methods for banks: UNKNOWN (ask Jose). [JOSE]

Layer 9. Languages, databases and cloud providers for Cush Core. UNKNOWN (ask Jose). Jose's published article states that ledger shards are backed by PostgreSQL. [JOSE] [SITE]

Operating model. In Jose's words, the most important thing to explain is how the platform is run, operated and upgraded: "It's not about the technology. Technology is the easy thing." The other key point is verticality: every function is built into the platform. [JOSE]

Public website (not Cush Core itself). cush-core.com is hosted on Vercel and built with TanStack Start and TanStack Router, React, Vite and Nitro. Its source is in a public GitHub repository: https://github.com/MEFolson/cush-core (no licence file declared). Checked 24 Nov 2026 via the GitHub API and HTTP headers.

## 9. FAQ for partners

Q: Does any bank use Cush Core under a licence today?
A: No licensees are claimed. Cush Core is licensable. Licensing discussions are planned from Q2 2027. [DECK]

Q: Does Cush Payments hold licences or process payments today?
A: No. It plans to apply for payments and electronic money licences in the UK, the US, the EU, Ghana and other African countries, with a target launch in June 2027 once licences are in place. [DECK] [JOSE]

Q: What is the Cush Blockchain, and is it a public chain?
A: It is a permissioned, immutable ledger designed for banks. Nodes are known and registered; every customer, account and contract keeps its own BLAKE3 hash linked chain; there is no single global chain and no general purpose consensus. [MATTHEW] [SITE]
